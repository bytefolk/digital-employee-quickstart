# 04 沉淀知识库

数字员工聪不聪明，九成取决于你喂了什么资料。这一篇讲怎么喂。

## 核心原则：用别人真实的问法当标题

引擎的工作方式是：把用户的问题跟你资料里的**段落**做匹配，找到最相关的几段，
再让大模型基于这几段组织答案。

所以**标题写得像用户的提问，命中率最高**。

❌ 不好的写法：

```markdown
## 差旅费用报销制度实施细则
```

✅ 好的写法：

```markdown
## 出差回来怎么报销
```

如果同一件事有好几种问法，**就都写在标题里，用 `/` 隔开**：

```markdown
## 怎么申请权限 / 权限找谁批 / 申请系统账号

先在 OA 提「权限申请」单，选最小够用的范围，直属主管审批。
需要生产环境权限的，还要加一位技术负责人审批。
```

这不是玄学，是实测过的。同一份资料、同一个问题，只改标题：

| 标题写法 | 问「值班时间是几点到几点」 |
| --- | --- |
| `## 值班时间` | ❌ 答"没找到足够依据" |
| `## 值班时间是几点到几点 / 值班时间 / 什么时候有人` | ✅ 正确回答并给出出处 |

原因是检索按关键词匹配段落。用户问句里多出来的"是几点到几点"会稀释匹配度，
标题里把这些说法都覆盖到，命中率立刻上去。

## 文件怎么组织

放在 `knowledge/` 目录下，用 `.md` 结尾，一个主题一个文件：

```
knowledge/
├── 入职必读.md
├── 报销流程.md
├── 权限申请.md
├── 系统报障.md
└── 常见问题汇总.md
```

文件名和标题都用中文没问题。目录可以有子目录（最多 3 层）。

## 一份好资料的样子

```markdown
# 报销流程

## 出差回来怎么报销

出差结束后 15 个工作日内在 OA 提交报销单。需要上传：
行程单、发票、审批通过的出差申请单编号。
超过 15 个工作日需要补一份说明。

## 打车费能报吗

因公打车可以报，需要在备注里写清楚起止地点和事由。
上下班通勤的打车费不能报。

## 报销多久能到账

财务每周三、周五各审一批。审批通过后 3 个工作日内打款到工资卡。
```

要点：

- **一个小节回答一个具体问题**，别把十件事挤在一段里。
- **写具体的数字和条件**（15 个工作日、周三周五），别写"尽快""按规定"。
- **说清楚边界**（因公可以报、通勤不能报），这样机器人不会含糊。
- 段落别太长。引擎会把长文切成约 1800 字的片段，自然分段有助于切得准。

## 越用越准：把真实问答沉淀下来

这是最有效的做法。每次有人问了机器人答不上来的问题：

1. 人工回答他；
2. 把这个问答对**用他原本的问法**写进 `knowledge/` 里；
3. 重启服务。

比如有人问"那个报销的事情要多久"，机器人没答上来。你就在
`knowledge/报销流程.md` 里补一节：

```markdown
## 报销要多久 / 报销的事情多久能办完

财务每周三、周五各审一批，审批通过后 3 个工作日内打款。
从提交到到账一般 5 到 8 个工作日。
```

积累两三个月，机器人就能接住绝大部分日常提问了。

## 改完一定要重启

```bash
bash scripts/start.sh
```

知识库是**进程启动时读进内存**的，不重启改了也没用。

想快速验证新加的内容有没有生效，用命令行（每次都是新进程，读的是最新文件）：

```bash
bash scripts/ask.sh "报销要多久"
```

答对了、并且 `Sources:` 里出现了你刚改的那个文件，就说明生效了。

## 什么不要放进知识库

- **任何密钥、密码、Token** —— 引擎会自动跳过文件名含 `secret`/`token`/
  `password`/`credential` 的文件和 `.env`，但别指望这个兜底，源头上就不要放。
- **客户个人信息、身份证号、手机号** —— 机器人的回答可能被截图转发。
- **还没定稿的方案** —— 机器人不知道"这只是草稿"，会当成正式答案说出去。
- **互相矛盾的两份旧文档** —— 要么删掉旧的，要么明确标注时间和适用范围。

## 除了本地文件，还能挂什么

`runtime/configs/local.json` 的 `sources` 支持三种数据源：

| 类型 | 用途 |
| --- | --- |
| `filesystem` | 本地目录下的 markdown 文件（默认用的就是这个） |
| `git` | 一个公开的 GitHub / GitLab 仓库，自动同步 |
| `dws` | 钉钉里的文档、AI 听记纪要、群聊记录、知识库、钉盘文件 |

`dws` 类型可以让数字员工直接读钉钉里的资料，但**必须逐条指定读哪个**——
它不会自己去翻整个企业的文档。配置方式见
[引擎的 DWS 连接器文档](https://github.com/fullstack-ai-infra/digital-employee/blob/main/docs/connectors/dws.md)。

如果你用的是 AI 助手，直接跟它说"我想让数字员工读钉钉里的某某文档"，它会帮你配。
