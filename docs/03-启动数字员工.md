# 03 启动数字员工

> [!WARNING]
> 本文是尚未交付的渠道部署方案历史草稿，不适用于公开 CLI `0.3.0`。该版本没有 quickstart
> 所描述的长期渠道服务，仓库也没有本文引用的 `scripts/`。当前可执行路径见
> [README.zh-CN.md](../README.zh-CN.md)。

## 第一步：下载引擎

```bash
bash scripts/setup-runtime.sh
```

它会把引擎代码下载到 `runtime/` 目录，安装依赖并编译。第一次跑要几分钟。

> **注意**：脚本用的是完整的 `npm install`（包含开发依赖）。如果你自己手动装，
> 千万不要用 `npm install --omit=dev` —— 编译需要 TypeScript 编译器，少了会报
> `sh: 1: tsc: not found`。

## 第二步：填好 .env

如果 `scripts/setup-dingtalk.sh` 跑过了，钉钉那两项已经自动填好了。你还需要补上
模型信息：

```bash
cp .env.example .env   # 如果还没有 .env
```

然后编辑 `.env`，填这三项：

```
MODEL_BASE_URL=https://你的模型接口地址/v1
MODEL_NAME=你的模型名
OPENAI_API_KEY=你的密钥
```

顺便可以改一下这句（**建议改成中文**）：

```
ESCALATION_MESSAGE=我在已批准的资料里没找到足够依据，这个问题需要请同事帮忙确认。
```

这是数字员工"查不到答案"时的固定回复。它是**写死的文本，不由模型生成**——
所以如果这里留着英文，不管别人用中文还是英文提问，都会收到英文回复。

## 第三步：放资料进知识库

数字员工**只会回答你喂给它的资料里有的内容**。把公司的手册、规章、FAQ 写成
markdown 文件，放到 `knowledge/` 目录：

```
knowledge/
├── 团队手册.md
├── 报销流程.md
└── 常见问题.md
```

怎么写效果最好，见 [04-沉淀知识库.md](04-沉淀知识库.md)。

先把示例文件删掉：

```bash
rm knowledge/示例-团队手册.md
```

## 第四步：生成配置

```bash
bash scripts/make-config.sh
```

它会读 `.env`，生成引擎需要的配置文件 `runtime/configs/local.json`。

**密钥不会写进这个配置文件** —— 配置里只写环境变量的名字，真实的值运行时才从
`.env` 读。这样万一配置文件被误传到 GitHub 也不会泄密。

## 第五步：先用命令行测一下

**别急着上钉钉。** 先在命令行里问一个问题，这样能立刻分清"是问答本身有问题"
还是"钉钉链路有问题"：

```bash
bash scripts/ask.sh "值班时间是几点到几点"
```

正常应该看到答案，末尾带 `Sources:` 引用来源。

- **答得对** → 知识库和模型都通了，可以继续。
- **答"没找到足够依据"** → 知识库里没有相关内容，回第三步补资料。
- **报错** → 大概率是 `.env` 里模型的三项配置有问题（地址、模型名、Key）。

## 第六步：启动服务

```bash
bash scripts/start.sh
```

看到 `服务已启动，钉钉长连接建立成功` 就好了。

这个脚本会自动停掉旧进程，所以**以后改完东西直接再跑一遍就是重启**。

## 第七步：在钉钉里试

打开钉钉，在搜索框里搜你给机器人起的名字，开始对话。

搜不到的话，先跑 `bash scripts/app-status.sh` 看版本审批状态——绝大多数情况是
审批还没通过。

## 日常命令速查

```bash
bash scripts/start.sh              # 启动 / 重启
```

```bash
bash scripts/stop.sh               # 停止
```

```bash
bash scripts/logs.sh               # 看日志（加 -f 持续跟踪）
```

```bash
bash scripts/ask.sh "问题"          # 命令行直接问，不走钉钉
```

```bash
bash scripts/app-status.sh         # 查钉钉应用和审批状态
```

## ⚠️ 最重要的一条规矩

**改完任何东西，都要重启服务。**

配置文件和知识库都是**进程启动时一次性读进内存**的，之后改文件对运行中的服务
毫无影响。以下情况都必须 `bash scripts/start.sh`：

- 改了 `knowledge/` 里的任何文件
- 改了 `.env`
- 重新跑了 `make-config.sh`

**不重启的典型症状**：你明明刚补了资料，命令行 `ask.sh` 也能答对，但钉钉里的
机器人还是回答"没找到足够依据"。
