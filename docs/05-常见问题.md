# 05 常见问题

## 钉钉里搜不到机器人

**最常见的原因：应用版本还没通过发布审批。**

```bash
bash scripts/app-status.sh
```

如果看到版本状态是 `AUDIT`，就是还在等审批。这时候：

- 后台服务能正常连上钉钉（日志有 `connect success`），说明密钥没问题；
- 但机器人在钉钉搜索里就是不出现，创建者之外的人也看不到；
- **只能等审批人在钉钉里点通过**，去催他。

如果状态是 `INIT`，说明版本创建了但没提交发布：

```bash
bash scripts/publish-app.sh
```

## 只有我自己能看到机器人，同事搜不到

可见范围里只有创建者。查一下：

```bash
bash scripts/app-status.sh
```

加人（把 userId 换成同事的）：

```bash
dws dev app member add --unified-app-id <你的appId> --user-id <同事的userId>
```

`unifiedAppId` 在项目根目录的 `.dingtalk-app.json` 里。

## 机器人一直回答同一句英文

比如一直回 `I do not have enough approved evidence. A maintainer should review
this question.`

这句话是**配置里写死的固定文本，不是模型生成的**。机器人在知识库里找不到相关
依据时，就原样返回这句。所以：

1. **为什么是英文**：因为引擎示例配置里默认写的就是英文。改 `.env` 里的
   `ESCALATION_MESSAGE` 成中文，重新 `bash scripts/make-config.sh`，再重启。
2. **为什么找不到依据**：知识库里确实没有相关内容，或者进程用的是旧知识库。

先用命令行测一下，能立刻分清是哪种：

```bash
bash scripts/ask.sh "你刚才问机器人的那个问题"
```

- 命令行**也**答不上来 → 知识库里真的没这内容，去补 `knowledge/`。
- 命令行答得对，钉钉答不对 → **进程用的是旧配置，重启就好**。

## 我明明改了资料，机器人还是老样子

**这是最容易踩的坑。**

配置文件和知识库都是**进程启动时一次性读进内存**的，不会自动重新加载。改完
必须重启：

```bash
bash scripts/start.sh
```

需要重启的情况：改了 `knowledge/` 里的文件、改了 `.env`、重新生成了配置。

判断方法：`scripts/ask.sh` 每次都开新进程，读的一定是最新文件。如果它答得对而
钉钉答得不对，100% 是该重启了。

## 报 `DingTalk Stream connect timed out after 20000ms`

上一条长连接在钉钉服务端还没释放完，新连接被拒了。

`scripts/start.sh` 已经内置了 5 秒等待。如果还是遇到，等 10 秒再跑一次就行：

```bash
bash scripts/start.sh
```

## 报 `sh: 1: tsc: not found`

编译需要的 TypeScript 编译器没装上，通常是依赖没装全。

```bash
cd runtime && npm install && cd ..
```

不要用 `npm install --omit=dev` 或 `npm ci --production`，编译器在开发依赖里。

## 停不掉服务 / kill 了还在

这个进程没做优雅下线处理，普通 `kill` 之后它可能还挂着底层的重连逻辑。

```bash
bash scripts/stop.sh
```

这个脚本会先正常 kill、等 5 秒、还在的话自动 `kill -9`。

## `dws auth login` 卡住不动 / 授权完没反应

如果你是在**服务器、容器、SSH 环境**里操作，必须加 `--device`：

```bash
dws auth login --device
```

不加的话它会让浏览器跳到 `127.0.0.1` 的本机地址，你的浏览器访问不到那台机器，
授权结果就回不来。

## 创建应用报权限错误

你的钉钉账号不是企业管理员。企业内部应用的创建权限只有管理员有。找 IT 或
管理员同事帮你走 [02-创建钉钉机器人.md](02-创建钉钉机器人.md) 那几步。

## 报 `机器人不存在，请先创建机器人`

顺序错了：直接跑了 `dws dev app robot enable`，但机器人还没创建。

必须先用 `robot config` 创建（`enable` 是给已存在的机器人用的）：

```bash
dws dev app robot config --unified-app-id <appId> --name "名字" --mode STREAM --add-scope --yes
```

`scripts/setup-dingtalk.sh` 里已经处理好了正确顺序。

## 模型报错 / 回答质量很差

先确认 `.env` 里三项配置对不对：

```
MODEL_BASE_URL=   # 注意要带 /v1 结尾（大多数服务是这样）
MODEL_NAME=       # 模型名要和服务商给的完全一致
OPENAI_API_KEY=   # Key 有没有过期、额度够不够
```

改完要重新生成配置并重启：

```bash
bash scripts/make-config.sh && bash scripts/start.sh
```

如果模型能正常回答但答得不准，问题一般在知识库，不在模型 ——
见 [04-沉淀知识库.md](04-沉淀知识库.md)。

## 机器人会不会乱操作 / 泄露资料

不会。这个岗位模板（`answer-agent`）默认是**只读**的：

- 不会审批、不会改数据、不会调用任何写操作的工具；
- 只读你明确配置的资料，不会自己去翻公司其他文档；
- 找不到依据时会转人工，不会编答案；
- 回答会带上出处，方便你核对；
- 引擎会跳过 `.env` 和文件名含 `secret`/`token`/`password` 的文件。

更多边界说明见引擎的
[SECURITY.md](https://github.com/fullstack-ai-infra/digital-employee/blob/main/SECURITY.md)。

## 还是搞不定

把出错的完整命令和报错信息贴给你的 AI 编程助手，让它按
[AGENTS.md](../AGENTS.md) 的排查表帮你处理。
